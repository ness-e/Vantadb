## Spec (decisiones)
| # | Decision | Opcion elegida | Evidencia |
|---|----------|----------------|-----------|
| 1 | Nombre registry | `BackendRegistry` (nombre del plan a validar) | plan lo propone; HashMap<BackendKind, factory> es lo idiomatico |
| 2 | Tipo factory | `fn(&str, &Config) -> Result<Arc<dyn StorageBackend>>` | firmas reales: Fjall/Rocks `open(path, config)`, InMemory `new()` (ignora args) |
| 3 | Clave del mapa | `BackendKind` (requiere `Hash` derive nuevo) | BackendPartition ya deriva Hash; BackendKind no lo tiene — 1 linea |
| 4 | Registro | En composicion: `default_registry()` registra las 3; `register()` para extension | OCP: nuevo backend = `register()`, sin editar init probado |
| 5 | `create()` sin match | Solo HashMap lookup + Err si falta (infallible en practica: default siempre registra las 3) | elimina el match 281-301 por construccion |
| 6 | Parse env | `BackendKind::from_name(&str) -> Option<BackendKind>` ("rocksdb"/"fjall"/"memory"/"in-memory"; None=desconocido) | config conserva su warn + default Fjall; handlers NO se toca |
| 7 | Display | `BackendKind::as_str()` ("fjall"/"rocksdb"/"in-memory") | mismos labels que handlers.rs:212-216 (cuando handlers migre, usa as_str) |
| 8 | Backend ficticio | Test registra factory fake que overridea InMemory en un registry fresco; `create()` usa el override sin tocar init.rs | prueba de extension aditiva (closed-enum: override demuestra el mecanismo) |
| 9 | Feature gates | Factories rocksdb/fjall devuelven el mismo `Error::Validation{backend_feature}` cuando el feature falta | mismos mensajes que init.rs:285-299 hoy |
| 10 | handlers.rs | NO se edita en este task | prohibido por contrato; solo provee `as_str()` para migracion futura |
