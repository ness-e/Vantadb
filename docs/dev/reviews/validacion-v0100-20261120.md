## Fallos encontrados y corregidos (commits)

1. **`test_config_mut_read_only_stays_consistent`** — `is_read_only()` no
   reflejaba `config_mut()` y `ensure_writable()` solo miraba la config
   mutable: un engine abierto RO podía "des-ROarse". Fix: bandera efectiva
   física OR config en `is_read_only()` y en el guard de escritura.
   (`ca643a479` gates adicionales en paths transaccionales,
   `request_compaction`, `gc_mvcc_versions`, `run_quantization_maintenance`.)
2. **`memory_limit: Some(0)`** tratado como cap de 0 bytes en vez de
   ilimitado — corregido en la instalación del `mem_growth_cap`.
3. **`prealloc_vstore_batch`** pasaba `needed+4096` como `required`
   (excedía el cap aunque `needed` cupiera) — ahora `required=needed` y el
   extra es hint `desired`.
4. **`consolidate_node_rejects_out_of_bounds`** — el test usaba
   `pack_offset(99, 64)` fuera de los 6 bits representables (assert en vez
   de error path); ajustado a un segmento OOB representable.
5. **`quiesce_batch_eviction`** — el test violaba el contrato
   `insert_lock` no-reentrante (llamaba al helper `_locked` sin el lock);
   reescrito para modelar el path real de quiesce.
6. **Python `ValidationError` tipada** para el cap de dimensión de
   vector (`75f8fadbb`) — `extract_vector` lanzaba `ValueError` plano.
7. **Python `Schema`/`Serialization` → `CorruptError`** (`9cd81079f`) —
   el mapa los enviaba a `ValidationError`, contradiciendo
   `.code()=VANTADB_CORRUPT` del core, la fila -32002 de MCP y la
   jerarquía §6.3 de ERROR_HANDLING.md.
8. **Test async Python stale** — mezclaba dims 3/4/8 en una DB;
   FIND-411 fija dimensión global única. Corregido a dim 8.
9. **e2e `import_v1_jsonl_path_normalizes`** (`073c5d87c`) — test stale
   pre-FIND-347: path absoluto sin `export_base_dir` → 422 por diseño.
   Nuevo `helpers::build_server_state_with()` configura el sandbox.
10. **Node `VantaDB` alias** (`21fb5b567`) — `napi build` borraba el
    parche `?? VantaDb` en cada regen → `VantaDB === undefined`.
    `scripts/patch-exports.mjs` idempotente, cableado en `npm run build`
    y `release-npm-node.yml`. Binario `.node` reconstruido (stale 4-nov).
11. **`vantadb_wasm.d.ts` drift** (`b8b26aa58`) — `backend` fantasma
    (wire emite `runtime_profile`), tier `"Warm"` inexistente,
    `graph_bfs/dfs` devolvían `bigint[]` declarado `string[]`,
    `closeAsync` ausente (FFI-02), bloque init-glue stale para el target
    bundler. Pkg reconstruido + probe runtime.

## Riesgo de proceso detectado

Sesión paralela commiteando en el mismo worktree (`docs/extraccion`)
— durante la auditoría un `--amend` absorbió un archivo ajeno
(`meilisearch.md`), detectado y corregido sin pérdida. Regla aplicada:
commits solo con `-- paths` explícitos, cero `reset`/`stash`/`--amend`.
