## Spec

### FIND-760 — el gate tiene que medir lo que viaja

**Hecho corregido (medido hoy):** el `pre-push` corría `dev-tools/verify.ps1` **siempre**, y su primer step es `cargo fmt --all -- --check` — **árbol completo**. El push de `FIND-152` (2 commits, ambos fmt-clean: `cargo fmt --check -p vantadb-wasm` → 0) fue bloqueado por WIP sin formatear **de otro carril** (`vanta-memory/src/core/conversation/consolidation.rs`, `vantadb-mcp/src/memory_scheduler.rs`). El hook además **no tenía `SKIP`**: la única salida era `--no-verify`, que apaga **todos** los gates.

**Decisiones:**

| Ítem | Decisión | Motivo |
|------|----------|--------|
| `fmt` | `rustfmt --check` **por fichero del rango** (`git diff --name-only @{u}..HEAD`), `--edition 2021` (todo el workspace es 2021, verificado) y `--config skip_children=true`, implementado en `dev-tools/fmt-range.ps1` | Es el único gate que se puede acotar a ficheros con exactitud: rustfmt formatea archivo a archivo. `skip_children` es **medido, no supuesto**: sin él rustfmt entra en los `mod` hijos y reporta diffs de ficheros **fuera** del rango (probado en `%TEMP%\fmtprobe`: `lib.rs` con `pub mod child;` reporta también `child.rs`; con la opción, solo `lib.rs`). El chequeo vive en PowerShell porque el shell del hook (Git Bash/WSL) **no** tiene `~/.cargo/bin` en el PATH — medido: `command -v rustfmt` → nada bajo WSL aunque exista el binario. |
| `check` / `clippy` / `audit` / `deny` / `nextest` | **Siguen siendo de árbol**, y solo corren **si el rango toca Rust** | No son acotables por fichero: una crate compila como unidad, los tests de integración comparten estado y un test no tiene fichero dueño. Acotarlos por rango dejaría el gate midiendo menos de lo que promete. Para el WIP ajeno está `SKIP=<gate>`. |
| Sin Rust en el rango | `verify.ps1 -Skip fmt,check,clippy,audit,deny,nextest,cli-probes,consumo-guard`; **sí** corren `docs-coverage` y la verificación del runbook de backup | Un push de docs/CI no tiene nada que compilar. CI corre los gates Rust en cada push a `develop` (RULES.md §1, `ci-rust.yml:123`). Se conserva lo que **sí** depende de docs. |
| `SKIP` | Mismo idioma que `pre-commit` (`SKIP=<id>[,<id>…]`), ids **idénticos** para Rust (`cargo-fmt`, `cargo-clippy`) + uno por gate. El gate saltado **se nombra** en el output | Copiar el idioma, no inventar otro. Nada de silencios: un skip mudo es un rojo disfrazado. |
| `SKIP` en CI | Si `CI` no está vacío, `SKIP` se **ignora** y se avisa | Pre-mortem (c): un `SKIP` exportado en un workflow apagaría gates en CI sin que nadie lo note. Hooks son locales, pero la guarda cuesta 3 líneas. |

### FIND-753 — el índice compartido revierte trabajo ajeno, con exit 0

**Hechos medidos:** `Unable to create .git/index.lock` 8 intentos seguidos (4 carriles); un commit concurrente horneó una copia stale de `Backlog.md` y **reapareció una fila borrada**; el índice quedó con staged pre-commit de `FIND-98` (`tests/cli_tests.rs`, −92 líneas) que un `git commit -a` habría borrado; y `MM Backlog.md` con deleción staged de 6 líneas contra un working tree igual a HEAD.

**Decisión:** política documentada **con el comando exacto** en `RULES.md`, y un helper que la hace ejecutable porque el exit code no es evidencia:

| Ítem | Decisión | Motivo |
|------|----------|--------|
| Política | `RULES.md` §10 (rango) y §11 (índice privado + verificación por contenido) | Es lo primero que muerde a cualquier wave multi-carril. |
| Helper | **Sí**: `dev-tools/git-commit-isolated.ps1` (~125 L) | El contrato dice "si te sale barato". Lo es: `read-tree` + `add` + `commit` + relectura de **fragmentos** desde `HEAD`. Probado en las dos direcciones: commiteó la sonda (happy path, con hooks) y con un `-ExpectAbsent` falso devolvió exit 1. El commit de cierre usó además la variante `hash-object`+`update-index` (abajo) porque `Backlog.md` tenía WIP de otro carril. |
| Cuándo **no** usarlo | `git add -p` interactivo, commit de un merge (`MERGE_HEAD`), commit que debe arrastrar lo que ya está staged en el índice compartido, y `--amend` (prohibido acá) | El helper parte de `HEAD` limpio: pisaría decisiones de staging deliberadas. |

**Techo declarado:** el helper **no** serializa contra otros carriles; reduce la ventana a `add`+`commit` (milisegundos) y detecta la reversión por contenido. No la impide. La contención real es un lock de wave, que no existe.
