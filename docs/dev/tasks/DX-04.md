# Task `DX-04..08`: Mejoras de Developer Experience (Python SDK, Hardware Profile y Quickstart)

## Scope (Allowed Files)
- `vantadb-python/src/lib.rs`
- `vantadb-python/src/types.rs`
- `vantadb-python/vantadb_py/vantadb_py.pyi`
- `vantadb-python/vantadb_py/__init__.pyi`
- `vantadb-python/vantadb/__init__.pyi`
- `docs/api/PYTHON_SDK.md`
- `src/hardware/mod.rs`
- `docs/user/QUICKSTART.md`

## Acceptance Criteria
1. `DX-04`: `vantadb-python` exposes `memory_node_id(namespace: str, key: str) -> int` (as module function and `VantaDB.memory_node_id` staticmethod) backed by `vantadb::sdk::serialization::memory_node_id`, with `.pyi` stubs and documentation in `docs/api/PYTHON_SDK.md`.
2. `DX-05`: `VantaDB.export_namespace` in `vantadb-python/src/lib.rs` emits a Python `UserWarning` when `report.records_exported == 0` so callers are warned when exporting an empty or typo'd namespace.
3. `DX-06`: `VantaPyListResult.total_count` in `vantadb-python/src/types.rs` and `docs/api/PYTHON_SDK.md` explicitly documents that `page.total_count` is the count of records in the current page/filter window and points to `db.count(namespace)` for full namespace cardinality.
4. `DX-07`: `HardwareCapabilities::load_or_run_benchmark` in `src/hardware/mod.rs` resolves the profile path via `VANTADB_PROFILE_PATH` env var, then `~/.vanta/.vanta_profile` (creating `~/.vanta` if needed), falling back to `.vanta_profile` in CWD only when no home directory is available.
5. `DX-08`: `docs/user/QUICKSTART.md` includes an Operational Notes section covering `record.key` / `record.payload` attributes, CLI path traversal (`..`) rejection, `/api/shutdown` lock recovery, and pre-allocated storage sizing.

## Verification Commands
- `cargo clippy --workspace --all-targets -- -D warnings`
- `cargo nextest run --profile audit -p vantadb --lib hardware`
