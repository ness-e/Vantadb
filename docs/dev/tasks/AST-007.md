## Rollback Plan for anti-stutter major (vantadb pre-1.0)

### Trigger Conditions
- Error rate > 2× baseline o P95 > 50% sobre baseline tras merge a main
- Reportes de breakage en consumidores (PyPI/npm/crates.io) por rename
- `semver-checks` post-merge no reporta major (mapa incompleto → release-plz bump erróneo)

### Rollback Steps
1. Sin flag (rename compile-time, no runtime): `git revert <merge-commit Release PR> && git push` + release-plz publica patch de reversión al siguiente merge. NO tags manuales, NO `cargo publish` manual.
2. Verificar rollback: `cargo check -p vantadb` + `just verify` + `rg Vanta` vuelve a hits pre-rename en aliases (aliases deprecated siguen resolviendo).
3. Comunicar: notificar en canal release + nota en docs/CHANGELOG.md vía release-plz (nunca a mano).

### Consideraciones de Datos
- Sin migración de datos (renames de tipos, cero cambio wire/serde/on-disk: `VantaHeader` y `VANTADB_*` intactos). Datos insertados: preservados.
- Aliases `#[deprecated]` + `@deprecated` + `DeprecationWarning` actúan como compat-shim: consumidores con versión vieja siguen compilando con warnings hasta el major siguiente.

### Tiempo estimado
- Revert + push: <5 min · Re-publish vía release-plz: <15 min · Sin migración DB: 0 min.
