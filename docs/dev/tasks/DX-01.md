## Investigation Notes

### Repro H-009 (determinista) — ANTES del fix

```js
import { Client } from "vantadb"; // 0.8.0 publicado (o pkg local)
const db = Client.create();
db.put({ namespace: "demo", key: "k", payload: "hello" }); // OK
db.get("demo", 5); // ❌ RuntimeError: memory access out of bounds
```

Stack raw (directo al wasm, sin wrapper):

```
RuntimeError: memory access out of bounds
    at wasm://wasm/006ed2b6:wasm-function[1828]:0x18e434
    at wasm://wasm/006ed2b6:wasm-function[1532]:0x14e486
    at passStringToWasm0 (.../vantadb_wasm_bg.js:1551:15)   ← firma exacta de H-009
    at Client.get (.../vantadb_wasm_bg.js:388:22)
```

- **Mecanismo (causa raíz):** `passStringToWasm0` recibe un no-string → `arg.length` = `undefined` → `len=undefined` → `malloc(undefined→0)` devuelve `align=1` → el branch `offset !== len` (0 !== undefined) toma el `realloc(ptr=1, old_size=0, new_size=NaN→0, 1)` (línea 1551) → `__wbindgen_realloc` opera sobre un puntero inválido → trap. La corrupción es del **marshalling**, no del engine.
- **Versiones probadas:** Node **22.23.3, 26.0.0, 26.8.1, 26.10.0** — trap idéntico en las 4 → **NO es específico de Node 26** (la atribución de H-009 era incidental: el validador corría Node 26).
- **Descartado como causa:** strings no-ASCII (fuzz 20k roundtrips ✅), crecimiento de memoria (bulk 2000 puts con vectores ✅), `memory.buffer` resizable de Node 26 (probado: sigue detachando igual que Node 22; `toFixedLengthBuffer`/`toResizableBuffer` son opt-in, MDN BCD #30541), ESM/CJS (ambos ✅), API stale (el error de positional args es un TypeError distinto).
- **Métodos afectados por la misma clase (verificado en el glue, `passStringToWasm0` call sites):** `get`, `delete`, `list`, `count`, `delete_by_filter`, `supersede`, `similar_to_key`, `generate_snippet`, `query`, `export_all`, `export_namespace`, `import_file`, `reindex_hnsw_from_text`, `audit_text_index(_deep)`, `insert_node(content)`, `delete_node(reason)`, `add_edge/remove_edge(label)`, `graph_*` (direction), `open/connect(path)`.
- **Fuentes web (verificadas):** Node 26 changelog (V8 14.6, "avoid deprecated Wasm API") `https://raw.githubusercontent.com/nodejs/node/main/doc/changelogs/CHANGELOG_V26.md`; MDN BCD "Node.js 26 adds WebAssembly.Memory buffer methods" `https://github.com/mdn/browser-compat-data/pull/30541`; wasm-bindgen tracker (sin issue upstream idéntico) `https://github.com/rustwasm/wasm-bindgen/issues?q=%22memory+access+out+of+bounds%22`.

### Después del fix (esperado)

`db.get({namespace:"demo", key: 5})` → coerce a `"5"` (encuentra el registro si existe) · `db.get({namespace:"demo", key: {}})` → `DbError VANTADB_INVALID_ARGUMENT` ("must be a string") sin trap.
